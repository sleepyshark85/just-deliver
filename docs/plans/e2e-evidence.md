## Keys that remain, and why

- **App Insights connection string** — set in each app as `APPLICATIONINSIGHTS_CONNECTION_STRING`. It is not a key: its instrumentation key only
  says which component telemetry goes to; it gives no read access and Microsoft documents it as not a secret. The platform still handles it as
  one: the template output is secret in Pulumi, and the E2E asserts it is never printed (`Assert.DoesNotContain("InstrumentationKey", …)`).
  Making it keyless too (the component's `DisableLocalAuth` with Entra ingestion through the app's identity, which already holds Monitoring
  Metrics Publisher) is a later change.
- **Log Analytics shared key** — the Container Apps environment (substrate, not a workload) ships logs with the workspace key
  (`catalog/templates/azure/container-apps-environment`, held as a Pulumi secret). No workload sees it. Removing it means the `azure-monitor`
  log destination with a diagnostic setting instead: a later change.
